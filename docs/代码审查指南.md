# 代码审查指南（接收协作者 PR）

> 面向维护者。规范依据 [`高考物理真题制作规范.md`](../高考物理真题制作规范.md)、
> [`AGENTS.md`](../AGENTS.md)、[`docs/新增年份SOP.md`](新增年份SOP.md)。
> 协作者看 [`CONTRIBUTING.md`](../CONTRIBUTING.md)。

## 一、接取远程 PR

本仓库同时有 `gitee`、`github`、`origin`(gitea) 三个远程。**Gitee PR 通过
`refs/pull/<编号>/head` 暴露，可拉到本地审查**（`refs/pull/<编号>/MERGE` 是合并预览）。

```bash
make fetch-pr PR=1                 # 默认 REMOTE=gitee；取到本地分支 pr/1 并打印 diff 概况
make fetch-pr PR=1 REMOTE=github   # 从 GitHub 取
git switch pr/1                    # 切过去审查（返回：git switch -）
```

等价的纯 git 命令：

```bash
git fetch gitee refs/pull/1/head:pr/1
# 长期配置（之后每个 PR 都可用 gitee/pr/N）：
git config --add remote.gitee.fetch '+refs/pull/*/head:refs/remotes/gitee/pr/*'
git fetch gitee
```

**在哪里审查？推荐直接在项目里**（`make pr-check` 已封装 fetch → 切分支 → `all`+`check`
→ 自动切回）：只在本仓库加一个本地分支，不改 `main`；但切分支要求**工作树干净**
（有 WIP 先提交/暂存）。

独立 worktree（如 `git worktree add /tmp/opencode/pr-N pr/N`）不扰动主工作树，
**但仓库外没有本地数据** `JSON/`、`Docx/`、`材料处理/`，`check_meta`/`check_material`
等会**静默跳过**，只适合纯 diff / TikZ / 代码比对，**不适合全量审查**。临时/渲染文件按
约定只写 `/tmp/opencode/`，但 worktree 并非必须。

先看改动范围，再决定审查深度（与远端基线 `gitee/main` 比较，避免本地 `main` 落后）：

```bash
git log --oneline --graph gitee/main..pr/1
git diff --stat gitee/main...pr/1
git diff gitee/main...pr/1
```

## 二、审查流程

### 1. 自动化快筛（先跑）

```bash
make pr-check PR=1     # 推荐：接取 + 对 PR 改动卷先 make all 再 check（要求工作树干净）
                       # 先编译（TikZ + 两版），才能查出编译期问题（如 TikZ 缺字）
# 或手工（PR 的改动是已提交的，check-changed 只认未提交改动，故不能直接用）：
make fetch-pr PR=1 && git switch pr/1
DIRS=$(git -c core.quotepath=false diff --name-only gitee/main...pr/1 \
       | awk -F/ '$1=="试卷" && NF>=3 {print $1"/"$2"/"$3}' | sort -u)
for d in $DIRS; do make -C "$d" check; done
make -C 试卷/<年>/<地区> student && make -C 试卷/<年>/<地区> teacher   # 两版都要能编
make check-docs                          # 进度/年份索引/异常记录一致性
make tools-test                          # 改了 tools/ 时
```

> `make check-changed` 只统计**工作树里未提交**的改动，用于自己边改边查；
> 审查别人**已提交**的 PR 分支请用 `make pr-check` 或上面的 `git diff … main...pr/N` 手工法。

> **本地数据不在库里**：`JSON/`、`Docx/`、`材料处理/` 是 Git 忽略的本地数据。
> - 协作者侧：`check_meta`（元数据↔JSON）、`check_material` 等**会跳过并提示**，`make check` 仍可过；
> - 维护者侧：**必须在本机有 `JSON/`、`材料处理/` 的工作树里复跑**，才能完成元数据逐字段比对与内容核对。
>   不要用 `git worktree` 到仓库外审查全量项——那里没有这些数据，会静默跳过。

### 2. 人工内容核对（脚本查不出的）

对照 `merged.md` / JSON / 原 PDF 逐题核对：题干与数据、上下标、公式、选项与答案、
填空答案、子图拆分与摆放、详解是否忠实（原卷评分标准、①②③编号）。

### 3. TikZ 重绘专项（本仓库高频）

规范允许**人工手绘**的 TikZ 重绘（默认禁止转换期重绘）。**标准提交**应满足：
命名与 `figs/<名>` 同名 + `TikZ/tikz_sources.json` 登记原图 + `.tex` 已用
`\onepicture{TikZ/<名>.pdf}` 接入。审查时：

```bash
python3 tools/check_tikz.py 试卷/<年>/<地区>          # 登记/引用一致性（make check-tikz）
make -C 试卷/<年>/<地区> tikz                         # 先编译 TikZ PDF
make -C 试卷/<年>/<地区> tikz-compare                 # 生成 tikz_compare/*_重绘前后.png
```

- **无需 `TikZ/originals/`**：原图已在 `figs/` 时，`tikz_sources.json` 的 `original`
  直接指向 `试卷/<年>/<地区>/figs/<名>.png` 即可（`check_tikz` 只要求该路径存在）。
- **非标准 PR**（只上传 `TikZ/*.tex`、未改正文、未登记原图）：`check_tikz` 会告警；
  `tikz-compare` **默认**也会为这些“孤儿源”出图 `tikz_compare/<地区>_未引用TikZ_重绘前后.png`
  （原图按 `TikZ/originals/<名>` → `figs/<名>` **同名**自动推断，`.svg` 自动渲染）。
  若文件名与 `figs` 不一致则配不到原图，输出会列出——应要求作者改名或补登记、接入。
  用 `python3 tools/tikz_compare.py <目录> --no-orphans` 可只看已接入的。

逐张核对**形状/方向/标注/比例**，重点查坐标轴变量、标注文字、箭头方向是否与原图一致。

### 4. 文档一致性

`进度记录.md` 该卷行、`异常记录/<年>.md`（统一结构、已解决置末）是否更新；
`试卷/<年>/README.md` 由 `make index` 生成，**不得手工编辑**；`make check-docs` 通过。

## 三、本项目审查清单（重点）

- [ ] 改动范围：只动 `试卷/<年>/<地区>/`（`<地区>.tex`、`figs/`、`TikZ/`、`Makefile`）及对应文档行；
      改共享文件（`tools/`、`*.sty`、`*.cls`、文档）需逐行严审。新增单位宏要审 `PhyUnit.sty`。
- [ ] **不夹带**：`JSON/`、`Docx/`、`材料处理/`、编译产物（`*_学生版.pdf`/`*_教师版.pdf`）、
      `*.log`/`*.aux`/`*.fls`/`svg-inkscape/`。但 **`试卷/**/figs/*.pdf` 与 `figs/*.svg` 是源图，必须入库**。
- [ ] 元数据 13 项齐全、顺序固定、取值与 JSON 一致（含空 `%% memo:`）。
- [ ] 选择题 `\xzanswer`/`\fourchoices[answer=]`/`%% answer` 三处一致；
      非选必有 `\jdanswer`/`\tkanswer` 且与小问一一对应。
- [ ] 每题一条**基本** `\memoanswer{}`（`\memoanswer[作者]{}` 不能替代）；缺详解写占位并登记异常。
- [ ] 图片只用 ChoiceQuestion 命令（禁 `figure`/`subfigure`/`pic/`）；命名“题号+子图字母”；
      引用标签格式 `年份+地区+题号+子图`。
- [ ] **严禁 TikZ 重绘**（除非人工手绘并登记）；有则查 `tikz_sources.json` + `tikz-compare`。
- [ ] 单位一律 PhyUnit（无裸单位）；`\frac` 非 `\dfrac`；数字间半角冒号；`$x-t$` 不写 `$x$-$t$`。
- [ ] 学生版/教师版均可编译；`make -C 试卷/<年>/<地区> check` 0 错误。
- [ ] `进度记录.md`、`异常记录/<年>.md` 已更新；`make check-docs` 通过。

## 四、Gitee 网页侧操作

- 在 PR 页面查看 diff、逐行评论、请求修改；**以本地 `make check` 结果为准**（仓库暂未接 CI）。
- 建议：将 `main` 设为保护分支、要求审查；合并前本地验证通过，**优先 Squash 合并**保持历史清晰。
- 审查意见可引用脚本输出（如 `check_glyphs` 的缺字、`check_tikz` 的孤儿提示）作为客观依据。

## 五、提交/合并后

- 若采用重绘：确认 `TikZ/tikz_sources.json` 已登记（原图在 `figs/` 时无需 `TikZ/originals/`），
  `.tex` 已接入，`tikz_compare` 已逐张核对。
- 若发现新异常：在 `异常记录/<年份>.md` 补登并按状态分区，`make check-docs`。
- 收尾 `make index`（如需）与 `make progress` 复核欠账。
