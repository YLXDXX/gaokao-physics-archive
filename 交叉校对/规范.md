# 交叉校对规范（他源成品 PDF ↔ 本仓库 LaTeX）

本规范规定如何借助**独立来源的成品 PDF** 对 `试卷/<年>/<地区>/` 的题目、答案、解析、
公式、单位、配图、题注、元数据等进行**交叉校对**，并统一素材命名、映射、状态记录与
流程，使后续校对可持续、可复核、可回滚。

> 本规范只管**交叉校对**；制卷本身仍以
> [`../高考物理真题制作规范.md`](../高考物理真题制作规范.md) 为准，
> 材料处理见 [`../材料处理与OCR规范.md`](../材料处理与OCR规范.md)，
> 图片尺寸见 [`../图片尺寸处理规范.md`](../图片尺寸处理规范.md)。

## 一、素材来源与裁定优先级

| 代号 | 来源 | 范围 | 形态 | 特点 |
| :--- | :--- | :--- | :--- | :--- |
| `tian` | 天利 38 套 | 2025–2026 | 试卷、答案**分离** | 出版物源，部分矢量配图，准确率最高 |
| `zhu` | 朱玉亮《1978 年至今 高考物理真题分类全汇编》 | 1978–2024 | 试卷、答案**分离** | 出版物印前源，除实物照片外为矢量图，准确率很高 |
| `liu` | 刘芳主持项目 | 1978–2026 | 教师版**合订** | 各老师校对排版，质量高；含简略答案、**无详解** |

- 素材统一放在本地目录 `ProofreadPDF/`（**已在 `.gitignore` 忽略，不入库**）：
  - `ProofreadPDF/2025-2026/<年>/<年>_<地区>.pdf`（天利试卷）
  - `ProofreadPDF/2025-2026/<年>/<年>_<地区>_答案.pdf`（天利答案）
  - `ProofreadPDF/1978-2024/<年>/<年>_<地区>.pdf`（朱源试卷）
  - `ProofreadPDF/1978-2024/<年>/<年>_<地区>_答案.pdf`（朱源答案）
  - `ProofreadPDF/1978-2026/<年>/<年>_<地区>.pdf`（刘源教师版合订）
- **冲突裁定优先级**：`tian` ＞ `zhu` ＞ `liu` ＞ 本仓库现有 JSON／材料／OCR。
  - 天利有的内容（2025–2026），以天利为准；其次朱源；两者都没有时以刘源为准。
  - 三源都无或明显缺漏时，回本仓库 `材料处理/`、`OriginPDF/` 与原始 JSON。
- **注意**：刘源 2024 上海为“网络回忆版”，可靠性低；遇到以朱源/原 PDF 为准，并在
  `异常记录/2024.md` 备注。
- 天利、朱、刘主要是**题干与简答**；若各源均无完整详解，**不得**把简答强行扩写成“原卷详解”。
  详解仍按本仓库既有详解/材料维护，冲突时以高优先级源的答案与题干为准并登记。
- **重复卷**：天利 2025 的 `西北四省` 与同树 `陕晋青宁` 为同一套（首题一致），
  已在 `overrides.json` 的 `ignore` 中排除扫描重复件，保留文字版（规范化后为 `陕晋宁青`）。

## 三、命名与映射

### 1. 规范化命名

源 PDF 在**各自源树内就地重命名**（保留 `2025-2026/`、`1978-2024/` 与
`1978-2026/` 三棵树）：

```
<年>/<年>_<地区>.pdf            # 试卷 / 教师版合订
<年>/<年>_<地区>_答案.pdf       # 试卷、答案分离的来源（天利、朱玉亮）
```

- `<地区>` 一般取**本仓库地区名**（与 `试卷/<年>/<地区>/` 一致）。
- 映射尚未确认（`uncertain`/`fuzzy`）或本仓库无对应卷时，取**源文件名解析出的地区 token**，
  避免“命名即断言已匹配”。
- 重命名前会校验目标重名/存在；原文件名逐条写入 `rename_manifest.json`，可据此回滚。
- 重命名是**幂等**的：再次运行不会重复改名；脚本会借 `rename_manifest.json`
  按**原始文件名**重新解析 token，保留别名/备注语义。

### 2. 地区别名（`overrides.json`）

源卷名与本仓库地区名不一致时，在 `overrides.json` 的 `aliases` 中登记：

```jsonc
{
  "aliases": {
    "*":    { "三南": "湖南云南海南" },                 // 全局：置信度 alias
    "2001": { "广东河南": "粤豫" },
    "2024": { "黑吉辽": { "region": "辽宁",            // 年份内优先于全局
                          "confidence": "alias",
                          "note": "经比对首题一致（同一套）" } },
    "2003": { "全国旧课程": { "region": null,          // 显式“仅源、本仓库无”
                              "confidence": "uncertain",
                              "note": "本仓库未收该单科卷" } }
  }
}
```

- 值可以是字符串（`confidence=alias`）或对象 `{region, confidence, note}`；
  `region: null` 表示**已知无对应卷**。
- 匹配顺序：同年精确 → 同年别名 → 全局别名 → 模糊匹配（`fuzzy`，仅提示）。
- 置信度：`exact`（同名）/ `alias`（人工确认同名卷）/ `uncertain`（存疑）/
  `fuzzy`（自动相似）/ `source-only`（仅源）/ `repo-only`（仅本仓库）。
- **年份内别名优先于全局别名**（如 `2024` 的“黑吉辽→辽宁”不会被全局“黑吉辽→黑吉辽内”覆盖）。
- 已确认的别名应在 `note` 写清依据（如“比对首题一致”）；不确定的标 `uncertain`，
  在表中显示为“待确认”。

### 3. 源有而我无 / 我无源可校

- **源有而我无**：列在 `交叉校对表.md` 第三节。若确属本仓库漏收，按
  [`docs/新增年份SOP.md`](../docs/新增年份SOP.md) 新建卷（**默认需要平台 JSON；
  不要直接从扫描 PDF 伪造 JSON**），并在 `进度记录.md`、`异常记录/<年>.md` 登记。
  暂不补者保留在表中。
- **缺卷补建例外**：仅经维护者明确授权时，可按 `异常记录/2008.md`、`2015.md` 的做法，
  以高优先级源 PDF + OCR 生成 JSON；须在 JSON 顶层 `_sourceNote` 标注“非平台原始 JSON”，
  完成答案/图片/双版编译/`make check` 验收，并在 `异常记录/<年>.md` 与 `进度记录.md` 登记。
  不得把该例外当作默认流程。
- **我无源可校**：列在 `交叉校对表.md` 第二节。该卷仍须完成常规 `make check`；
  交叉校对状态记 `无源`，不得伪造“已交叉校对”。

## 四、状态与总表

### 1. 状态取值（`status.json`）

| 状态 | 含义 |
| :--- | :--- |
| `未开始` | 尚未开始交叉校对 |
| `素材就绪` | 已找到对应源 PDF（及必要 OCR/材料），尚未逐题核对 |
| `校对中` | 正在逐题核对 |
| `已完成` | 已逐题核对并记录结论；必要修正已编译/自查通过 |
| `待人工核验` | 存在疑点（源冲突无法裁定、疑似缺题、回忆版等），需人工复核 |
| `无源` | 天利、朱、刘三源均无对应试卷，无法交叉校对 |

`status.json` 结构：

```json
{
  "sets": {
    "2024/辽宁": {
      "status": "未开始",
      "date": "2026-11-24",
      "note": "朱源逐题核对：改正题干 2 处、答案 1 处；配图按朱源矢量替换 1 张"
    }
  }
}
```

- 每个仓库卷在首次 `make proofread-plan` 时自动补默认条目（不覆盖已有记录）。
- `note` 建议写：用了哪份源、核对了哪些字段、改了哪些、发现的问题去向。
- 状态为 `待人工核验` 时，必须在 `异常记录/<年>.md` 有对应条目（类别取现有枚举，
  如 `来源`/`答案`/`公式`/`图片编号` 等，问题中注明“交叉校对”）。

### 2. 总表

`交叉校对表.md` 由 `mapping.json` + `status.json` 生成，包含：

1. **逐卷交叉校对表**（按年份分组）：天利/朱源/刘源是否可用、可用源、校对状态、最后更新、备注；
2. **本仓库有卷、他源均无**：无法交叉校对的卷清单；
3. **他源有、本仓库无对应卷**：源多出的卷清单（附原始文件名）；
4. 状态说明。

**不要手工编辑总表**；更新 `status.json` 后执行 `make proofread-table`。

## 五、逐卷交叉校对流程

> 前置：已按第六节完成该卷 OCR（或至少可阅读源 PDF）。一般先跑
> `make proofread-plan && make proofread-table`，再用 `make proofread-show UNIT=<年>/<地区>`
> 确认源文件。

1. **确认素材与映射**
   - `make proofread-show UNIT=2024/辽宁`：核对天利/朱/刘源文件是否存在、置信度与备注。
   - 若映射错误：改 `交叉校对/overrides.json` → `make proofread-plan` → 再核对。
2. **确定底本**
   - 天利有 → 以天利为底本；否则朱源；再否则刘源；三源都无 → 跳过（状态 `无源`）。
   - 先通读源卷目录/题号，确认题数、题型、分值、选做/必做结构与本仓库一致。
3. **逐题核对**（至少覆盖下列字段，逐项打勾）：
   - **完整性与结构**：题号、题数、题型、分值、选做/必做、模块说明；题干、选项、小问、
     答案、详解、提示、评分标准是否有漏题/漏问/漏段；题目与答案中的配图是否齐全。
   - **题干与选项**：文字、数据、单位、上下标、符号、正负号、有效数字；选项内容与顺序
     （选择题）、答案字母（单选/多选）。
   - **答案与详解**：非选择题小问划分与 `\jdanswer`/`\tkanswer` 一一对应；计算题答案
     `enumerate` 与小问一一对应，实验题答案可手动编号对应；答案、提示、解析、评分标准中
     的公式编号（①②③…）是否连续、引用是否悬空；解析“引图而图不在”是否补齐。
   - **公式**：符号、下标、分式、根号、方向、矢量记号；行内、行间分式**一律 `\frac`，
     禁用 `\dfrac`**；公式编号与正文引用一致。
   - **单位**：一律 `PhyUnit`；`\Uxxx` 均已在 `PhyUnit.sty` 定义。遇缺失单位按
     `../LaTeX_format_ReadMe.md` 第 11 条新增：在外部 `../PhyUnit/` 项目的 `.sty` 中按
     命名规范添加并写注释，同步其手册/README/文档，重新编译测试；本仓库文档/异常记录注明。
   - **图片**：见下方「3.1 图片专项」。
   - **元数据**：题型、分值、章节、考查点等（以平台 JSON 为准，源 PDF 用于核对题意；
     缺卷例外卷以本地补录 JSON 为准，并已在 `异常记录/<年>.md` 标注）。
   - **详解**：与答案是否自洽；源无详解时不得臆造，缺者仍按规范占位并登记。

### 3.1 图片专项（交叉校对必查）

- **逐张拆分**：ABCD 图片选项、图甲乙丙丁、图 abcd 等必须**每张独立成文件**；不得把
  多个选项/子图拼在一张图中。多子图用 `\twopicture…\ninepicture`，图片选项用
  `\fourchoices[ispicture=true]`，每个选项一张图。
- **去标题/标号**：图片中不得保留图题、题注、“图1/图甲/A/B/C/D”等标题与标号；标题和
  编号由正文/宏自动生成。HQ 图可用 `crop` 裁掉；无法去除时按 `异常记录` 登记
  （类别 `图片编号`/`复合图`）。
- **自动引用**：正文引用图片、表格等编号一律用 `\ref{标签}`（表格/公式同理），
  **禁止手写“图甲/图1/图A”**；标签按 `年份+地区+题号+子图字母`，与图片命令的 `label=`
  一致；`\onepicture` 给了 `label` 时必须同时给 `num=`/`fig=`，避免 `\ref` 恒显示“a”。
- **引用间距**：`\ref{}`/`\eqref{}`/`\pageref{}` 前后与其它文字之间留一个**空格**（或 `~`），
  如 `如图 \ref{2026云南08a} 所示`、`由表 \ref{...} 可知`；不得写成 `图\ref{...}中`。
- **尺寸检查**：目视核对图片在版面中的宽/高是否合适（过大、过小、过高、超版心、挤压
  正文、拉伸变形）；异常按 `../图片尺寸处理规范.md` 修正，不能修正的登记
  （类别 `图片尺寸`，写明宽高/页码/原因）。
- **答案图/解析图**：题目图、答案图、解析图都要核对；解析文字提到图而图不在的，补齐或登记。

4. **修正 LaTeX**
   - 只改必要内容；严格遵守制作规范（`ChoiceQuestion` 图片命令、`PhyUnit` 单位、
     `\frac`、核素 `\ce{}`、自动编号、`\ref` 引用与间距等）。
   - **禁止**为了“像源 PDF”而引入 TikZ 重绘或原生 `figure`。
   - 图片缺/糊：优先从天利/朱源矢量 PDF 无损提取或按 `图片尺寸处理规范.md` 处理；
     不经允许不用源 PDF 截图替换 JSON 清晰图。
   - 可先用 `python3 tools/textfix/textfix.py --check` 查 `\dfrac`/冒号/公式连字符；
     用 `python3 tools/check_review.py --ref-audit` 查 `\ref` 间距与手写图号；
     用 `python3 tools/check_units.py --suggest` 查裸单位与缺失宏。
5. **编译与自查**
   - `make -C 试卷/<年>/<地区> student && make -C 试卷/<年>/<地区> teacher`
   - `make -C 试卷/<年>/<地区> check`（须 0 错误）
6. **异常闭环与登记**
   - **开始该卷前**先查 `异常记录/<年>.md` 中该地区未闭合条目（`make proofread-show UNIT=…`
     会列出）；逐条处理：能解决的在交叉校对中一并改正并改 `已解决`，不能解决的保留原状态
     并在「问题/处理建议」写明交叉校对结论（依据哪份源、为何不能解决）。
   - 交叉校对新发现的缺题/缺图/缺详解/公式/单位/文字/答案/图片编号/图片尺寸等，按六列表
     记入 `异常记录/<年>.md`；类别取现有枚举，问题中注明“交叉校对：天利作…，朱源作…”；
     能当场解决的直接写 `已解决`。
   - **修改源 JSON**：确认平台 JSON 确有错误（题号、题干、选项、答案、元数据等）时，允许修改
     `JSON/<年>/<年_地区>.json`；但必须同步 `.tex` 的元数据/内容，在 `异常记录/<年>.md`
     登记（类别 `平台数据`/`来源` 等，写明修改项与依据），并在 `status.json` 的 `note` 说明；
     改后重跑 `check_meta.py` 与 `make check`。PDF 补充题仍按 `% pdf-only: true` 处理。
   - 更新 `交叉校对/status.json`（状态、日期、结论/改动摘要）；
   - 更新 `进度记录.md` 该卷说明（如“已交叉校对天利/朱源；解决异常 N 条”），
     并刷新 `异常记录.md` 的相关总述（如有）；
   - `make proofread-table`、`make proofread-check`；
   - 必要时 `make index && make check-docs`。
7. **复核**
   - 状态改 `已完成` 前，建议第二人/第二轮按同一流程复核；发现新问题改 `待人工核验`
     并登记，不直接覆盖原结论。
   - 完成前跑 `make proofread-precheck UNIT=<年>/<地区> ARGS=--strict-refs`：
     `\ref` 间距门禁 + 全卷 `check` 均须通过；同时列出的手写图号提示也须逐条改正。

## 六、OCR 流程（增量/重跑）

他源 PDF 的 OCR 产物放 `交叉校对/材料/<源>/<年>/<年>_<地区>...`（本地忽略）。
使用外部 `ocrpipe`（OvisOCR3 底本 + PaddleOCR-VL 验证 + pdftotext 旁证），规则同
[`../材料处理与OCR规范.md`](../材料处理与OCR规范.md)。

```bash
# 1) 只看计划（不加载模型；建议先跑）
make proofread-ocr-plan

# 2) 全量启动（极耗时；Paddle 自动启停、逐页断点续跑；中断后重复即可续跑）
make proofread-ocr-batch

# 3) 只跑某一卷/某些文件（ARGS 透传 --only，按路径子串匹配）
make proofread-ocr-batch ARGS="--only 2024/2024_辽宁"
```

- 输出根分别为 `交叉校对/材料/2025-2026`、`交叉校对/材料/1978-2024`、

## 十、HighQualityPic 高质量矢量配图

`ProofreadPDF/HighQualityPic/` 收录逐图导出的**矢量 PDF**（试题图与答案图分文件夹），
来源包括**朱玉亮 1978–2024**与**天利 2025–2026**。当前 415 套中 **350 套有 HQ**
（朱 316、天利 34），约 **7861 个图文件**（朱 7050、天利 811）。
它比 JSON/扫描图更清晰，但**不是每套卷都有**，且逐图对应的题号需人工确认。

### 1. 目录、命名与清单

- 源结构：`HighQualityPic/<年>/<源卷文件夹>/<源卷>_p<页>_Fm<图号>.pdf`。
  天利导出文件为 `_p<页>_f<图号>`（小写 f，按页编号）。
- 规范化（`make hq-rename-apply`，可 `hq-rename-revert` 回滚）：
  - 文件夹：`<年>_<地区>`（试题图）、`<年>_<地区>_答案`（答案图）；
  - 文件（中间名，确认题号后再在 `figs/` 内改为 `<题号><子图>.pdf`）：
    - 朱玉亮（`Fm` 全卷唯一）：`<年>_<地区>_FmN.pdf` / `_答案_FmN.pdf`；
    - 天利（按页编号）：`<年>_<地区>_p<页>_Fm<图号>.pdf` / `_答案_p<页>_Fm<图号>.pdf`
      （保留页号，避免跨页 `Fm` 重名）。
  - 天利 2025 的 HQ 文件夹原为 `2025_西北四省`（与 PDF 源重复件同套），
    已规范化并入 `2025_陕晋宁青`；PDF 源仍按 `overrides.json` 的 `ignore` 排除重复扫描件。
  - 2002 `辽宁` HQ 与 `2002_全国理综旧课程` 为同套重复件，已在 `overrides.json` 的
    `hq_ignore` 排除；2009 `辽宁` HQ（“辽宁、宁夏卷”）已归并为 `2009_宁夏理综`。
- 清单：
  - `交叉校对/hq_mapping.json`：HQ 文件夹 ↔ 本仓库卷、图文件数量/尺寸；
  - `交叉校对/HighQualityPic表.md`：逐卷可用性总表（自动生成，勿手改）；
  - `交叉校对/hq_rename_manifest.json`：原名称 → 规范化名（可回滚）。

```bash
make hq-plan                    # 扫描 HQ → hq_mapping.json + HighQualityPic表.md
make hq-rename                  # 预览文件夹/文件规范化
make hq-rename-apply            # 执行（可 make hq-rename-revert 回滚）
```

- HQ 有、本仓库无的卷（如 2002/2009 辽宁、2015 10 月浙江等）列在总表第二节；
  本仓库有、HQ 无的卷不强行替换，保持原图。

### 2. 逐图匹配（必须人工核对）

```bash
make hq-match UNIT=1978/全国
```

- 生成 `交叉校对/hq_figmap/<年>_<地区>.json` 与对照图
  `交叉校对/hq_compare/<年>_<地区>/`（本地忽略）。
- 匹配方式：渲染 HQ PDF 与现有 `figs/`，去白边灰度特征 + 匈牙利一对一；分数仅作参考，
  **低分不等于匹配错**（矢量/位图、彩色/黑白、标注差异都会拉低分数），必须看对照图。
- 答案图：HQ `..._答案` 文件夹对应 `figs/<题号>_an*`；试题图对应非 `_an` 图。
- 确认后编辑 figmap：
  - `status` 改为 `"apply"`（默认 `auto`/`review`/`unmatched` 不会替换；
    替换成功后工具自动改为 `"applied"`，重新匹配需 `--force`）；
  - 需要裁掉图内“图1/甲/乙”等编号时，填 `crop: [x0,y0,x1,y1]`（归一化、左上原点）；
  - 无法对应/本仓库无此图：保留 `unmatched`，并在 `note` 写明原因。
- `\twopicture`…`\ninepicture`、`\fourchoices[ispicture=true]` 会按单图键
  （`wA/hA`…）更新；其他无法自动识别/更新的图片命令会跳过并在终端列出，需人工处理。

### 3. 替换与尺寸

```bash
make hq-apply UNIT=1978/全国                 # 预览
make hq-apply UNIT=1978/全国 ARGS=--write    # 执行
```

- 只处理 figmap 中 `status: "apply"` 的条目；成功后自动改为 `applied`，避免重复替换。
- **图片尺寸一律取 HQ PDF 的物理尺寸（cm）**；若 `crop`，取裁剪后的 PDF 尺寸。
  同时回填 `.tex` 的 `w=`/`h=`（保留 `align`/`num` 等选项）。
- 旧图移到 `figs/.ocr_before/`（本地忽略，便于对照/回退）。
- 同步更新该卷 `figures.manifest.json` 与 `figures.map.json`（本地忽略）：
  `source.kind=hq-pdf`、`width_cm/height_cm`、`final.basis=hq-pdf`、`status=hq`。
- 记录写入 `交叉校对/hq_apply_log.json`（入库），包含原图、HQ 源、尺寸、裁剪。
- 替换后必须：

```bash
make -C 试卷/<年>/<地区> student && make -C 试卷/<年>/<地区> teacher
make -C 试卷/<年>/<地区> check
python3 tools/figsize_check.py 试卷/<年>/<地区>
```

### 4. 与异常记录、交叉校对的衔接

- 交叉校对时，若该卷有 HQ 图，**优先按本节替换**；替换成功即可消除
  `异常记录/<年>.md` 中相应的“缺图/图片模糊/图片编号/图片尺寸”等问题，并把状态改为
  `已解决`（类别取现有枚举）。
- 不能替换的，写明原因（如多图命令无法自动更新、HQ 图与本题不符、HQ 无该图、
  图内编号无法裁除、本仓库图与 HQ 结构差异大等），仍以 `待人工核验`/`待处理`
  记入 `异常记录/<年>.md`。
- 每替换完一卷，在 `交叉校对/status.json` 的 `note` 中注明“已用 HQ 配图替换 N 张”，
  并刷新 `make proofread-table`；替换明细见 `hq_apply_log.json`。
- HQ 图不一定覆盖全部图：未覆盖的继续用原图；不得因为追求矢量而删图或改题意。
